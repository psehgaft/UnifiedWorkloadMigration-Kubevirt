Unified Workload Migration with KubeVirt

A hands-on path from containers and Kubernetes to a functional Linux VM running an HTTP service.

Workshop overview

Duration: 1–2 days, or modular half-day sessions · Audience: developers, system administrators, and platform engineers with basic Linux knowledge · Format: short theory sessions and hands-on labs.

1. Container foundations

Understand containers as isolated processes sharing the host kernel; compare them with VMs. Explore OCI image layers, registries, and containerd/CRI-O runtimes. Build, run, inspect, and optionally push a simple image with Podman.

2. Kubernetes foundations

Explore the control plane and worker nodes, then work with Pods, Deployments, Services, ConfigMaps, and Secrets. Practice kubectl and declarative manifests by deploying a multi-container application and exposing it.

3. Kubernetes networking

Follow the Pod networking model and CNI responsibilities. Compare ClusterIP, NodePort, and LoadBalancer Services, plus Ingress/Route. Apply a NetworkPolicy and verify traffic behavior.

4. Kubernetes storage

Compare ephemeral storage with PV/PVC-backed storage. Work with StorageClasses, dynamic provisioning, access modes, and reclaim policies. Restart a workload and verify its data survives.

5. KubeVirt concepts

Learn why VMs run on Kubernetes and how virt-api, virt-controller, virt-handler, and libvirt/QEMU fit together. Compare VirtualMachine, VirtualMachineInstance, and DataVolume resources. Discuss how VM networking and storage use Kubernetes primitives.

6. Deploy Kubernetes and KubeVirt

Check cluster readiness, install KubeVirt with its operator (or OpenShift Virtualization on OpenShift), and install CDI for disk management. Create VMs from container disks or imported images, attach PVCs, expose a Service, and use the console. Try live migration only when the cluster supports it.

7. Operations and next steps

Monitor VMs and containers together, size CPU and memory, troubleshoot common failures, and review security practices. Discuss when to choose containers or VMs, then explore live migration at scale, GPU passthrough, Windows guests, and GitOps.

Final exercise: a functional VM

Import a cloud-init disk with CDI, start a persistent Linux VM, install a web server, expose it through a Kubernetes Service, and verify its HTTP response with curl. Participants finish with a reproducible manifest and evidence that the VM and service work.

  1. Prepare the cluster, namespace, and image URL.
  2. Import the image into a DataVolume/PVC.
  3. Start the VM and check guest initialization.
  4. Port-forward the Service and verify the page with curl.
